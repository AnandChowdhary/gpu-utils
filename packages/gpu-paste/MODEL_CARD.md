# Model card: gpu-paste

## Task
Understand pasted text: detect what it is and extract structured fields, on-device.
Input: arbitrary clipboard text. Output: a `kind` (22 values), a confidence, entity
`spans`, a `parsed` payload and diagnostics. See README.md for the exact layering: 15 kinds
and 10 span kinds are decided by validated rules; the model decides 6 kinds and 6 span kinds.

## Architecture
- Tokenizer: character-class runs (`@gpu-utils/runtime` `tokenize()`); 10 hashed feature ids
  per token (word 1024, consonant skeleton 256, shape 8, 2-char prefix 128, 2-char suffix
  128, UTF-16 length 16, column-in-line 6, line-from-start 5, line-from-end 3, bias 1),
  no learned vocabulary
- Family: `ScanTagger(feature_rows=1575, hidden=32, tags=13, pooled_out=6, scan_layers=1)`
  from `gpu_utils_training.models`, unmodified. The CPU forward pass is the runtime's
  `scanTaggerForward` and the WebGPU path is `runScanTagger` on the canonical
  `scan_tagger.wgsl` (both parity-tested against the Python reference on every CI run).
- Embedding: one 1,575 × 32 table, summed per token
- Sequence mixing: one bidirectional gated affine scan (`h = a·h₋₁ + (1−a)·tanh(u)`,
  `a = σ(x Wa + ba)`, 32 channels per direction) → residual 5-tap depthwise conv over the
  64 concatenated channels → mean-pooled context (64)
- Heads: the family's per-token head `relu([x_t ‖ ctx] W + b)` 128 → 64 → 13 BIO labels
  (O + B/I × person, company, address, date, money, phone), decoded with the runtime's
  constrained Viterbi (`bioTransitions` + `bioStartMask`, no learned CRF); the family's
  pooled head `relu(ctx W₁ + b₁) W₂ + b₂` 64 → 64 → 6 kinds (address, contact, prose,
  list, code, markdown). `src/index.ts` splits the two outputs; nothing model-specific
  lives in the package.
- Parameters: 68,659 (50,400 embedding + 18,259 scan/conv/heads); the deleted bespoke
  model was 66,339
- Quantization: int6 symmetric per-tensor, quantization-aware training (STE) from epoch 1
  through `gpu_utils_training.loop.train` (AdamW, warm-up + cosine, best checkpoint)
- Inference windows: 512 tokens; kind logits are averaged over windows (on WebGPU all
  windows of one paste run as a single batched dispatch)

## Training data
Synthetic-first, 160,000 training examples + 8,000 held-out (different seed), generated by
`training/gpu_paste/data.py`:
- **address** (15 %): Faker street/city/postcode pieces laid out in 15+ national formats
  (US, UK, CA, AU, NZ, IN, IE, DE, AT, CH, FR, ES, MX, IT, NL, BR, PT, SE, PL, TR, CZ, DK,
  NO, FI, HU, RO, RU, ID, JP, KR, CN), one-line and multi-line, PO boxes, country lines
- **contact** (18 %): signatures, labelled cards, one-liners, business cards, bare names,
  company + address blocks, header lines ("Kontakt", "Guest:") in EN/DE/FR/ES
- **prose** (22 %): 130+ filler sentences (incl. capitalised non-entities: products,
  places, codes, units) and 70+ slot templates with person / company / address / date /
  money / phone / email / url / code slots, 1–5 sentences, EN/DE/FR/ES/PT
- **list** (12 %): 20 bullet styles, comma lists, agendas with times, quantities, reference
  codes, people-with-status, header lines
- **code** (12 %): templated snippets in 16 languages (JS, TS, Python, Go, Rust, Java, C/C++,
  Ruby, Shell, SQL, CSS, PHP, Swift, Kotlin, C#, YAML/TOML/env)
- **markdown** (10 %): headings, paragraphs, bullets, links, fences, quotes, tables, task
  lists, emphasis
- **structured, kind masked** (7 %): JSON, CSV/TSV, HTML, logs, key=value, e-mail headers
  with entities inside (trains the span head only)
- **single entity** (4 %): a bare person/company/address/date/money/phone
- Money in 20+ locales (~100 surface forms), dates in ~110 forms (ISO, numeric, month
  names in EN/FR/DE/ES, relative phrases, times), phones in ~55 national formats
- Noise: case flips, leading/trailing whitespace, typo-free (see limitations)

Sources and licences (nothing below ships in the package; see THIRD_PARTY_NOTICES.md):
- Faker (MIT) for names, addresses, companies in 30+ locales
- US Census Bureau 1990 name files (public domain), downloaded at training time
- SEC EDGAR `company_tickers.json` (public domain), downloaded at training time
- Not used: OpenAddresses (per-source, share-alike sources), libpostal/gpu-postal corpora
  (ODbL), CoNLL-style NER (research licences)

The generator was revised once, before this refactor, after inspecting failure
*categories* (not individual cases) on the unfamiliar set: missing first-name-only people,
venue-style companies, units/quantities, reference codes, agenda times, capitalised
non-entities and header lines. The unfamiliar numbers are therefore not a clean estimate of
generalisation for either model below; they are, however, the *same* numbers for both,
since the generator, the held-out seed and the hand-written set are unchanged by this
refactor. The set itself was never edited after being written.

## Evaluation

This release replaced the package's hand-written model with the shared `ScanTagger` family.
Both models are scored here on the **same evaluation sets with the same metric code**, on
this branch:

- *custom* = the model on `main` (66,339 params), its committed int6 weights loaded back
  into the old `PasteModel` and run through today's `evaluate.py`.
- *shared* = the `ScanTagger` retrain shipped in `model/` (68,659 params, seed 1).

The synthetic held-out set is regenerated from seed 1001 by the unchanged generator, so the
absolute numbers differ slightly from the previous card (which reported them on an earlier
draw); both models are scored on the draw described below. The hand-written set

### Is the kind regression real? Seed sensitivity

The two lost kind cases are 2 of 47 (and 2 of 77 end to end), so three seeds of the shared
family were trained with the default config (only `--seed` changed) and scored on the same
sets. The promoted checkpoint is seed 1, the documented default; it was **not** chosen on
these numbers.

| Run | held-out kind | held-out span F1 | unfamiliar kind (heads) | unfamiliar span F1 | end-to-end kind | end-to-end span F1 |
|---|---|---|---|---|---|---|
| custom (main) | 0.9923 | 0.9820 | 0.9149 (43/47) | 0.6025 | 94.8 % (73/77) | 72.8 % |
| shared, seed 1 (shipped) | 0.9930 | 0.9864 | 0.8723 (41/47) | 0.6278 | 92.2 % (71/77) | 74.3 % |
| shared, seed 2 | 0.9927 | 0.9872 | 0.9362 (44/47) | 0.5991 | 94.8 % (73/77) | 73.5 % |
| shared, seed 3 | 0.9925 | 0.9856 | 0.8936 (42/47) | 0.6087 | 93.5 % (72/77) | 72.9 % |

Read honestly: on the 7,291-example held-out set all three shared seeds beat the custom
model on both metrics. On the 47/77-case hand-written set the shared family spans 41–44
correct kinds (92.2–94.8 % end to end) and the custom model's single checkpoint sits inside
that band, so the shipped checkpoint's 2-case deficit is not distinguishable from seed
noise at this sample size — but it is also not disproved, and the shipped model *is* the
worst of the three seeds on that set. Seed 2 scores marginally higher on the held-out
selection score (1.9799 vs 1.9794) and would have been a defensible promotion; it was left
unpromoted so that the default seed keeps reproducing the shipped artefacts.

## Size and latency

Measured on this branch, Node 24, one shared CPU box; "custom" is `main` rebuilt and
re-benchmarked here, not the number from the previous card.

| Measure | custom (main) | shared ScanTagger | Δ |
|---|---|---|---|
| Package (min + Brotli, incl. int6 weights, kernel, rules) | 50.9 KiB (52,134 B) | 53.7 KiB (54,974 B) | +2,840 B |
| Weights alone (Brotli) | 37,667 B | 39,195 B | +1,528 B |
| Parameters | 66,339 | 68,659 | +2,320 |
| Budget | 60,000 B | 60,000 B | 8.4 % headroom |
| CPU path, short contact (23 tokens), warm | 0.70 ms | 0.95 ms | +36 % |
| CPU path, 1 KB paste (411 tokens), warm | 10.6 ms | 15.3 ms | +44 % |
| CPU path, 8 KB paste (3,294 tokens, 7 windows), warm | 82 ms | 120 ms | +46 % |
| First call (module import + int6 decode + one parse) | ≈ 23 ms | ≈ 19 ms | — |
| WebGPU cold start (device + 7 pipelines + weight upload) | ≈ 50–100 ms (estimate; no GPU on the build box, kernels verified on lavapipe) | | |
| WebGPU warm call, 1 KB paste | ≈ 1–3 ms, readback-dominated (estimate); all windows of a paste are now one batched dispatch | | |
| Training (2 CPU threads) | 426 s | 556 s + ~90 s data generation | 8 epochs either way |

The CPU path got ~45 % slower for ~3.5 % more parameters. About a third of that is real
arithmetic (the family adds a 5-tap depthwise conv and a wider per-token head: 128 → 64
instead of 96 → 48, ≈ 16 % more multiply-adds per token); the rest is the generic runtime
forward pass materialising `[x_t ‖ ctx]` per token, where the deleted bespoke `cpu.ts`
folded the constant pooled half of the head into a bias once per sequence. The WebGPU path
is unaffected by that (the kernel is the canonical one) and now batches all windows of a
long paste into a single dispatch.

Parity: CPU logits match `model/fixtures.json` (PyTorch on the decoded int6 weights) at
1e-4; the canonical `scan_tagger.wgsl` on Mesa lavapipe matches the fixtures to
max |Δ| = 1.5e-05 over all 25 fixtures in one dispatch.

## Limitations and intended use
- Probabilistic for the six learned kinds and six learned span kinds; deterministic
  elsewhere. Not a validator: `email`/`url`/`phone` mean "looks like", not "valid".
- Trained only on synthetic text; no typos, OCR noise or non-Latin word boundaries in
  training. CJK text is one letter-run per line for the tokenizer.
- Over-tags entities in real prose (see unfamiliar precision); use span `confidence`
  (mean token probability) and `diagnostics.kindProbabilities` to gate UI actions.
- Single-label kind; long mixed pastes are classified by the average over 512-token windows.
- Day/month order in `03/04/2024` is guessed and flagged in `diagnostics.notes`.
- English-centric relative dates ("next Tuesday") in rules; other languages only via the
  model's span head.

## Checkpoint
- Promoted: 2026-09-18, seed 1, epoch 7 of 8 (`training/runs/default/best.pt`, int6 export
  in `model/`), selected on held-out `kind accuracy + span F1`; held-out kind accuracy
  0.9930, span micro-F1 0.9864
- Training command: `cd training && uv run python -m gpu_paste.train && uv run python -m gpu_paste.export`
  (defaults: `--n 160000 --epochs 8 --seed 1 --threads 2`; 556 s of training plus ~90 s of
  data generation, CPU only). `uv run python -m gpu_paste.export` is deterministic from
  `best.pt`: re-running it reproduces the committed `model/` byte for byte.
